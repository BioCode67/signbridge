# 2026-08-18 작업 — 수어로 묻고 위치로 답한다 · 번역 오역 사냥

## 1. 「묻기」 — 물어보는 쪽이 생겼습니다

지금까지 이 앱에서 농인은 정보를 **받기만** 했습니다. 재난문자를 수어로 보고,
창구 직원의 말을 수어로 봤습니다. 정작 급할 때 필요한 것은 **묻는 쪽**입니다.
"대피소 어디예요?"는 들을 수 있는 사람이면 지나가는 사람에게 물어 3초에 끝내는
일이고, 농인에게는 그 3초가 통째로 막혀 있습니다.

```
카메라 앞에서 수어 → 낱말 인식 → 의도 파악 → 내 위치로 답 생성
                                → 아바타가 수어로 답 + 방향 지도
```

폰에서 `#/app` → **📹 묻기** → 가운데 큰 원형 버튼.

### 화면 문법을 영상통화로 잡았습니다

농인에게 영상통화는 **이미 배운 대화 방식**입니다(수어 통역 서비스가 그 형태입니다).
그래서 사용법을 새로 가르치지 않아도 "카메라 보고 수어하면 상대가 수어로 답한다"가
바로 통합니다.

- 물을 때는 **카메라가 화면 전체** — 내 손이 잘 잡히는지 봐야 합니다.
- 답할 때는 **아바타가 전체**, 카메라는 구석으로 작아집니다.
- **손을 내리면 알아서 답합니다.** 버튼을 눌러야 답이 나오면 그건 대화가 아니라
  조작입니다. 뜻이 확실할 때만 그러고, 애매하면 '답 받기'를 누르게 둡니다.

### 알아들을 수 있는 것

| 물으면 | 답 |
|---|---|
| 대피소·학교 + 어디 | 방향·거리·이름 + 방향 지도 |
| 병원 / 약국 / 경찰서 / 지하철 / 화장실 + 어디 | 같은 방식 |
| 지진·태풍·불 + 지금·무엇 | 지금 들어온 재난 정보 요약 + 원문 |
| 어떻게 (+재난) | 그 재난의 행동요령 — 줄마다 눌러서 수어로 |
| 도와주세요 | 곧바로 긴급 화면(주변 사람에게 보여주는 빨간 화면) |

**인식 후보까지 봅니다.** 모델의 1순위 정답률은 0.7863, 5순위 안에 들 확률은
0.9188입니다(실측). 1순위만 보면 다섯 번에 한 번은 의도를 놓칩니다. 순위별로
가중치를 낮춰 합산하고, 기준을 넘을 때만 판정합니다.

**못 미치면 "모르겠어요"라고 답합니다.** 억지로 하나를 고르면 엉뚱한 대피소를
알려주게 되고, 사용자는 그쪽으로 걸어갑니다. 재난 상황에서 그것은 침묵보다
나쁩니다. 그래서 검사 사례 27건 중 절반 가까이가 **오검출 사례**입니다.

### 지도 타일을 쓰지 않았습니다

재난 때 가장 먼저 끊기는 것이 통신입니다. 타일을 받아 그리는 지도는 **정작 필요한
순간에 회색 화면**이 됩니다. 그래서 내 위치를 한가운데 두고 주변을 상대 위치로
직접 그립니다 — 데이터가 이미 기기에 있으니 비행기 모드에서도 그대로 뜹니다.

- 나침반이 있으면 **내가 보는 쪽이 위**로 옵니다. 화살표 쪽으로 그냥 걸으면 됩니다.
- 위치 오차를 원으로 그립니다. 오차가 크면 방향도 믿으면 안 되니까요.
- 골목까지 필요하면 '지도 앱으로 열기'가 있습니다(그때는 통신이 필요합니다).
- 길 모양은 그리지 않습니다 — 도로 데이터가 없습니다. **없는 것을 그린 척하지
  않습니다.**

### ⚠️ 대피소 목록은 아직 참고용입니다

지금 실린 3,888곳은 OpenStreetMap에서 받은 것이라 **공식 지정 대피소가 아닙니다.**
데이터 파일이 그 사실을 들고 있고 화면이 그대로 "참고용"이라고 씁니다.
공공데이터포털 키가 있으면 한 줄로 바뀝니다:

```bash
python3 ml/tools/build_nearby.py --gov-key <키>   # 행정안전부 표준데이터
```

대피소를 사실과 다르게 말하는 것은 정보가 없는 것보다 나쁩니다.

## 2. 번역 오역을 **찾는 도구**를 만들었습니다

`북동쪽 → km 지진 크기`를 잡다가, 같은 모양의 오역이 얼마나 더 있는지 알 방법이
없다는 것을 깨달았습니다. 표현률은 이런 오역을 **성공으로 셉니다** — 수어가 나가긴
나갔으니까요.

```bash
python3 ml/tools/suspect_align.py --top 60
```

낱말과 글로스가 **글자를 하나도 공유하지 않고**, 그런데도 **자주 나오고**, 사전의
다른 조각으로 **분해되지도 않는** 것만 좁힙니다. 175,843개 중 1,002개.
전부 오역은 아니라서(대피→도망은 맞습니다) 자동으로 지우지 않고 목록만 냅니다.

빈도 상위에서 나온 것들:

| 낱말 | 실제로 나오던 수어 | 고친 뒤 |
|---|---|---|
| 있겠습니다 | 소나기 | 있다 |
| 많겠습니다 | 구름 | 많다 |
| 받겠습니다 | 고기압 | 받다 |
| 없어 | 공식 | 없다 |
| 같은 | 동광우방 | 같다 |
| 크게 | 차이 | 크다 |
| 매우 | WHO | 심하다 |
| 착용 | 마스크 | 입다 |
| 부산시 | 회의 | 부산 |
| 발열시 | 463 | 발열 |
| 에서 | IC | (지움 — 조사입니다) |
| 입니다 | mm | (지움) |

원인은 셋이었고 전부 구조적이었습니다.

1. **순수 문법 어미가 공기 통계에 먹혔다.** "많겠습니다"의 뜻은 '많다'인데, 날씨
   문장에서 늘 '구름'과 함께 나오니 통계가 구름을 1순위로 올렸습니다. 이 부류는
   빈도와 무관하게 어간의 뜻을 씁니다.
2. **관측이 얇은 활용형**도 마찬가지. 기준값은 0·20·50·200·400·800·1500으로 돌려
   **바뀌는 매핑을 한 줄씩 눈으로 보고** 정했습니다. 그 과정에서 예외 넷이
   필요하다는 것이 드러났습니다(사고→사다, 아니→알다, 떨어집니다→떨다가 되던 것).
3. **행정단위·시점을 뗀 어간이 사전에 있는데** 통짜 키의 통계가 이겼습니다.
4. **관형형 `-는`이 활용형 목록에 아예 없었습니다.** 받는·먹는·없는·맞는·넘는 —
   한국어에서 가장 흔한 꼴인데 통째로. 그 자리를 통계 잡음이 채우고 있었습니다.
5. **ㅂ 불규칙이 `-아/어`만 만들고 `-우니·-우세요`를 안 만들었습니다.**
   그래서 "길이 미끄러우니"의 미끄러우니가 '익숙하다'였습니다 — 빙판길 안내에서
   이 낱말이 빠지면 문장이 통째로 무너집니다.
