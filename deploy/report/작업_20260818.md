# 2026-08-18 작업 — 수어로 묻고 위치로 답한다 · 번역 오역 사냥

## 1. 「묻기」 — 물어보는 쪽이 생겼습니다

지금까지 이 앱에서 농인은 정보를 **받기만** 했습니다. 재난문자를 수어로 보고,
창구 직원의 말을 수어로 봤습니다. 정작 급할 때 필요한 것은 **묻는 쪽**입니다.
"대피소 어디예요?"는 들을 수 있는 사람이면 지나가는 사람에게 물어 3초에 끝내는
일이고, 농인에게는 그 3초가 통째로 막혀 있습니다.

```
카메라 앞에서 수어 → 낱말 인식 → 의도 파악 → 내 위치로 답 생성
                                → 아바타가 수어로 답 + 방향 지도
```

폰에서 `#/app` → **📹 묻기** → 가운데 큰 원형 버튼.

### 화면 문법을 영상통화로 잡았습니다

농인에게 영상통화는 **이미 배운 대화 방식**입니다(수어 통역 서비스가 그 형태입니다).
그래서 사용법을 새로 가르치지 않아도 "카메라 보고 수어하면 상대가 수어로 답한다"가
바로 통합니다.

- 물을 때는 **카메라가 화면 전체** — 내 손이 잘 잡히는지 봐야 합니다.
- 답할 때는 **아바타가 전체**, 카메라는 구석으로 작아집니다.
- **손을 내리면 알아서 답합니다.** 버튼을 눌러야 답이 나오면 그건 대화가 아니라
  조작입니다. 뜻이 확실할 때만 그러고, 애매하면 '답 받기'를 누르게 둡니다.

### 알아들을 수 있는 것

| 물으면 | 답 |
|---|---|
| 대피소·학교 + 어디 | 방향·거리·이름 + 방향 지도 |
| 병원 / 약국 / 경찰서 / 지하철 / 화장실 + 어디 | 같은 방식 |
| 지진·태풍·불 + 지금·무엇 | 지금 들어온 재난 정보 요약 + 원문 |
| 어떻게 (+재난) | 그 재난의 행동요령 — 줄마다 눌러서 수어로 |
| 도와주세요 | 곧바로 긴급 화면(주변 사람에게 보여주는 빨간 화면) |

**인식 후보까지 봅니다.** 모델의 1순위 정답률은 0.7863, 5순위 안에 들 확률은
0.9188입니다(실측). 1순위만 보면 다섯 번에 한 번은 의도를 놓칩니다. 순위별로
가중치를 낮춰 합산하고, 기준을 넘을 때만 판정합니다.

**못 미치면 "모르겠어요"라고 답합니다.** 억지로 하나를 고르면 엉뚱한 대피소를
알려주게 되고, 사용자는 그쪽으로 걸어갑니다. 재난 상황에서 그것은 침묵보다
나쁩니다. 그래서 검사 사례 27건 중 절반 가까이가 **오검출 사례**입니다.

### 지도 타일을 쓰지 않았습니다

재난 때 가장 먼저 끊기는 것이 통신입니다. 타일을 받아 그리는 지도는 **정작 필요한
순간에 회색 화면**이 됩니다. 그래서 내 위치를 한가운데 두고 주변을 상대 위치로
직접 그립니다 — 데이터가 이미 기기에 있으니 비행기 모드에서도 그대로 뜹니다.

- 나침반이 있으면 **내가 보는 쪽이 위**로 옵니다. 화살표 쪽으로 그냥 걸으면 됩니다.
- 위치 오차를 원으로 그립니다. 오차가 크면 방향도 믿으면 안 되니까요.
- 골목까지 필요하면 '지도 앱으로 열기'가 있습니다(그때는 통신이 필요합니다).
- 길 모양은 그리지 않습니다 — 도로 데이터가 없습니다. **없는 것을 그린 척하지
  않습니다.**

### ⚠️ 대피소 목록은 아직 참고용입니다

지금 실린 3,888곳은 OpenStreetMap에서 받은 것이라 **공식 지정 대피소가 아닙니다.**
데이터 파일이 그 사실을 들고 있고 화면이 그대로 "참고용"이라고 씁니다.
공공데이터포털 키가 있으면 한 줄로 바뀝니다:

```bash
python3 ml/tools/build_nearby.py --gov-key <키>   # 행정안전부 표준데이터
```

대피소를 사실과 다르게 말하는 것은 정보가 없는 것보다 나쁩니다.

## 2. 번역 오역을 **찾는 도구**를 만들었습니다

`북동쪽 → km 지진 크기`를 잡다가, 같은 모양의 오역이 얼마나 더 있는지 알 방법이
없다는 것을 깨달았습니다. 표현률은 이런 오역을 **성공으로 셉니다** — 수어가 나가긴
나갔으니까요.

```bash
python3 ml/tools/suspect_align.py --top 60
```

낱말과 글로스가 **글자를 하나도 공유하지 않고**, 그런데도 **자주 나오고**, 사전의
다른 조각으로 **분해되지도 않는** 것만 좁힙니다. 175,843개 중 1,002개.
전부 오역은 아니라서(대피→도망은 맞습니다) 자동으로 지우지 않고 목록만 냅니다.

빈도 상위에서 나온 것들:

| 낱말 | 실제로 나오던 수어 | 고친 뒤 |
|---|---|---|
| 있겠습니다 | 소나기 | 있다 |
| 많겠습니다 | 구름 | 많다 |
| 받겠습니다 | 고기압 | 받다 |
| 없어 | 공식 | 없다 |
| 같은 | 동광우방 | 같다 |
| 크게 | 차이 | 크다 |
| 매우 | WHO | 심하다 |
| 착용 | 마스크 | 입다 |
| 부산시 | 회의 | 부산 |
| 발열시 | 463 | 발열 |
| 에서 | IC | (지움 — 조사입니다) |
| 입니다 | mm | (지움) |

원인은 셋이었고 전부 구조적이었습니다.

1. **순수 문법 어미가 공기 통계에 먹혔다.** "많겠습니다"의 뜻은 '많다'인데, 날씨
   문장에서 늘 '구름'과 함께 나오니 통계가 구름을 1순위로 올렸습니다. 이 부류는
   빈도와 무관하게 어간의 뜻을 씁니다.
2. **관측이 얇은 활용형**도 마찬가지. 기준값은 0·20·50·200·400·800·1500으로 돌려
   **바뀌는 매핑을 한 줄씩 눈으로 보고** 정했습니다. 그 과정에서 예외 넷이
   필요하다는 것이 드러났습니다(사고→사다, 아니→알다, 떨어집니다→떨다가 되던 것).
3. **행정단위·시점을 뗀 어간이 사전에 있는데** 통짜 키의 통계가 이겼습니다.
4. **관형형 `-는`이 활용형 목록에 아예 없었습니다.** 받는·먹는·없는·맞는·넘는 —
   한국어에서 가장 흔한 꼴인데 통째로. 그 자리를 통계 잡음이 채우고 있었습니다.
5. **ㅂ 불규칙이 `-아/어`만 만들고 `-우니·-우세요`를 안 만들었습니다.**
   그래서 "길이 미끄러우니"의 미끄러우니가 '익숙하다'였습니다 — 빙판길 안내에서
   이 낱말이 빠지면 문장이 통째로 무너집니다.

## 3. 화면을 실제로 찍어 보고 나서야 보인 것들

e2e는 "버튼이 있는가"를 잽니다. 그래서 전부 통과했는데, 사진을 찍어 보니
묻기 화면이 이랬습니다.

| 사진에서 본 것 | 왜 생겼나 |
|---|---|
| **카메라 칸이 0px** — 버튼만 화면 맨 위, 아래는 통째로 까맣게 | 감싼 요소가 블록이라 `flex-1`이 듣지 않았습니다 |
| **탭 막대가 통째로 사라짐** — 다른 화면으로 나갈 길이 없음 | 시작 화면에서도 전체화면으로 접고 있었습니다 |
| 촬영 중에도 나갈 길 없음 | **✕ 그만** 버튼을 넣었습니다 |

아바타도 잘려 있었습니다. 3D 카메라가 세로로 1.05m만 담아서 **손을 머리 위로
올리는 동작에서 손이 화면 밖으로 나갔습니다.** 수어에서 손 위치는 뜻의 일부라
잘리면 그 문장을 읽을 수 없습니다. 1.34m를 담게 바꿨습니다 — 아바타가 조금
작아지지만 **잘린 손보다 작은 손이 낫습니다.**

창구 대화의 아바타 칸은 화면의 33%뿐이었습니다. 답 카드는 굴려서 볼 수 있지만
수어는 작으면 못 읽습니다. 42vh로 키웠습니다.

같은 고장을 다시 놓치지 않도록 둘을 남겼습니다.

```bash
npm run build && python3 scripts/shots.py    # 사진만 찍는다 — 보기 좋은가는 사람이 본다
```

그리고 e2e에 **자리 검사**를 넣었습니다 — 카메라 칸 높이 > 200px, 버튼이 화면
아래 절반에. 고치기 전 값은 0px / 화면 맨 위였습니다. 고친 뒤 실측: **759px /
nav 759px(화면 844px)**.

받기 화면의 낱말 진행 줄도 손봤습니다. 재난문자는 18낱말이 예사라 전부 깔면
작은 글씨 세 줄이 되고 그만큼 아바타가 밀립니다. **앞뒤 다섯 낱말만** 남기고
양끝에 `…`를 둡니다 — 전체 진행은 위쪽 진행바가 이미 보여 줍니다.

## 6. 고정 주소로 옮기기 — 준비해 뒀습니다

무료 터널이라 60분마다 주소가 바뀌는 문제, `deploy/PAAS.md`에 정리했습니다.
**서버가 필요 없는 정적 사이트**라 옮기는 건 쉽습니다 — `npm run build` 하고
`dist/`를 올리면 끝입니다.

권장은 **Cloudflare Pages**입니다. 무료이고 **대역폭 제한이 없습니다**(다른 곳은
월 100GB에서 막히는데, 오프라인 전체 세트가 72MB라 몇 사람만 받아도 찹니다).
계정만 있으면 `dist/` 폴더를 웹에 끌어다 놓는 것으로 5분이면 됩니다.
깃에 연결해 두면 그 뒤로는 푸시할 때마다 자동입니다.

배포에 필요한 것은 이미 넣어 뒀습니다 — `public/_headers`(캐시·권한 정책),
`public/_redirects`. **서비스워커와 index.html은 캐시 금지**로 잡았습니다.
캐시되면 새 배포가 영영 안 내려갑니다.

### 준비하다 발견한 것 — 오프라인이라고 적어 두고 반쪽이었습니다

수어 인식이 MediaPipe 런타임과 모델을 **CDN에서 받아 오고 있었습니다.**
회선이 끊기면 **카메라가 아예 켜지지 않습니다** — 물어볼 수가 없으니 답도 없습니다.
정작 그때가 "대피소 어디?"를 물어야 하는 때입니다. 인터넷이 있는 곳에서는 잘 되니
화면으로는 보이지 않았고, 요청 로그를 보고서야 알았습니다.

32MB를 동봉했습니다. 곁가지로 **아무도 안 쓰는 ORT wasm 13.5MB**와
**참조되지 않는 데모 파일 3.9MB**도 찾아 지웠습니다.

### 하나 더 — 고정 주소로 옮겼으면 그대로 재현될 뻔한 것

서비스워커가 `data/`·`models/`를 **캐시 우선**으로 잡고 있었습니다. 그런데
`align.json`·`glosses/*`·`model.onnx`는 **이름이 그대로**입니다. 그래서
번역 사전을 다시 만들어도, 인식 모델을 갈아 끼워도, **한 번 방문했던 사람에게는
영영 옛것이 나갑니다.** 캐시 이름은 JS 번들 해시로 만드는데 사전만 바뀐 배포에서는
번들이 그대로라 저절로 풀리지도 않습니다.

이 프로젝트에서 이미 같은 모양으로 당했습니다 — 60에폭을 돌리는 동안 앱에는
에폭 27짜리 모델이 붙어 있었고, 화면상 차이가 없어 아무도 몰랐습니다.
오늘만 사전을 다섯 번 다시 만들었으니 고정 주소로 옮기자마자 재현될 참이었습니다.

해시가 붙은 번들만 캐시 우선으로 두고, 나머지는 **캐시를 즉시 돌려주고 뒤에서
새것으로 갈아 끼우는 방식**으로 바꿨습니다. 다시 받는 비용은 크지 않습니다 —
조건부 요청이라 안 바뀌었으면 304로 끝납니다.

## 7. 시각·날짜를 사람이 쓰는 꼴로

"수어가 자연스럽지 않다"를 파고들다 **가장 흔한 자리**에서 어긋난 것을 찾았습니다.

사람 번역가는 "21시"를 `시:9시`, "10.26(화)"를 `날짜:10월26일 화요일`이라는 **전용
동작**으로 냅니다. 말뭉치에서 `시:*`가 **17,149회**, `날짜:*`가 **6,640회** — 가장
많이 쓰는 부류입니다. 우리는 그 조각을 웹 사전에서 통째로 빼 놓고 숫자를 자릿수로
읽고 있었습니다("이 십 일 시"). **형식도 어법도 틀린** 셈이었습니다.

그리고 **시간대 표지**가 핵심이었습니다. 수어 시각은 12시간제라 `시:9시`만으로는
**오전 9시인지 밤 9시인지 알 수 없습니다.** 어느 시각에 어느 표지가 붙는지 원문
**26,000여 건에서 직접 셌습니다** — 23시는 밤 100%, 8시는 아침 94%, 12시는 낮 92%.

```
원문   1.7(목)~1.10(일)까지 임시선별검사소 운영
사람   날짜:1월7일 목요일1 물결표1 날짜:1월10일 일요일1 까지1 임시1 …
지금   날짜:1월7일 목요일1 물결표1 날짜:1월10일 일요일0 임시1 …
```

곁가지로 **`발생했` → `광산`**(지명)도 잡았습니다. 과거형 `-했`이 활용형 목록에
없어서, 재난문자에서 가장 흔한 서술 꼴이 지명으로 나가고 있었습니다.

재난문자 95.9% → **96.1%** · 오역 회귀 **114건 통과** · 나머지 집합 그대로.
