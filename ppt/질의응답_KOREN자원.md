## 2. 자원별 답변 카드

### ① AI Cloud (CHEETAH) — 학습 전용

**할당 자원**: `h200-mig-1g.35gb` · vCPU 16 · RAM 128Gi · 볼륨 900GiB

**실제로 한 일**

| 항목 | 수치 |
|---|---|
| AI Hub 실데이터 수신 | 약 133GB (§5에서 내역 확인) |
| ETL 가공 | 약 40만 클립 (재난안전 160,801 + 수어영상 WORD 약 24만) |
| 학습 표본 | 2,151,092 세그먼트 |
| 학습 처리량 | 에폭당 21~25분 · 60에폭 |
| 산출 모델 | iso-v2(인식 13,576클래스) · t2gs-v2(번역) · ctc-v1(연속) · g2ts-v1(복원) |
| 순간 최대 디스크 | 약 320GB (aihubshell이 download.tar→조각→병합으로 3배까지 부푼다) |

**여기서만 할 수 있는 이야기 — MIG가 아키텍처를 정했다**

`h200-mig-1g.35gb`는 **메모리는 35GB로 넉넉한데 연산은 FP32 17.14 TFLOPS로
H200 전체의 약 29%**다. 비대칭이다. 그래서 영상 3D CNN을 포기하고
**랜드마크 트랜스포머 2.8M 파라미터**를 골랐다.

> "자원 제약이 구조를 정했고, 그 구조가 결과적으로 서비스 요건과 맞았습니다.
> 랜드마크 입력은 영상의 약 1/2,000이라 이 GPU에서 에폭이 분 단위로 끝났고,
> 같은 모델이 20MB로 줄어 **브라우저 안에서 그대로 돌아갑니다.**
> 영상 CNN을 골랐다면 학습도 못 끝냈고 서버 없는 배포도 불가능했습니다."

**자원을 놀리지 않은 증거**: GPU 할당량이 1개라 iso-v1(인식)과 t2g-v1(번역)을
**같은 MIG에서 동시에** 돌렸다. 둘의 병목이 다르기 때문이다 — 인식은 데이터로더(CPU),
번역은 행렬곱(GPU). 합계 처리량 손실을 감수할 만한 거래였다. 모니터링에서 GPU
사용률이 낮게 나오면 모델이 작은 게 아니라 데이터로더가 못 따라가는 것이라
`--workers`를 올렸다.

### ② HPC 이노베이션 허브 — CPU 전처리

**왜 필요한가**: 영상→랜드마크 변환은 **순수 CPU 작업**(프레임 파싱·위생검사·압축)이고
클립마다 완전히 독립이다. AI Cloud의 vCPU 16개로 12,000클립에 약 40분이 걸리는데,
5배 규모를 AI Cloud에서 돌리면 **그 시간 내내 H200이 논다.**

**준비된 것** (저장소에 있다 — 심사위원이 확인 가능)

```bash
# VM 4대에 나눠 제출
for i in 0 1 2 3; do
  qsub -v SHARD=$i,NUM_SHARDS=4,KIND=WORD,ANGLES=U,D,L,R ml/jobs/pbs_slconvert.sh
done
python -m ml.etl.merge_index --data "$DATA_ROOT"   # 끝나면 인덱스 병합
```

- 샤딩은 **정렬된 전체 목록을 `[shard::num_shards]`로** 나눈다 → 겹침도 누락도 없다
- `--resume`과 함께 써도 안전하다 (노드가 죽어도 이어서)
- `merge_index`가 중복과 **팩이 실제로 없는 레코드**(중간에 죽은 노드)를 걸러낸다
- VM 2대 이상 만들면 PBS Torque와 passwordless SSH가 자동 구성된다 (8/5 교육에서 습득)

**8월 4주 계획**: 다각도(U/D/L/R) 48,000클립 분산 변환 → 다각도 학습으로 인식 강건성 향상.
VM 4대(8코어×4)면 AI Cloud 단독 대비 약 1/4 시간이고, 산출물인 팩은 클립당 수십 KB라
AI Cloud로 옮기는 비용이 거의 없다.

### ③ KOREN VM — 상시 데모 (9월)

- 프런트엔드(`dist/`) 정적 호스팅 + **Q&A 백본 서버**(`server/app.py`, FastAPI)
- NOC이 방화벽 정책을 잡아 주므로 외부 접근 서비스에 맞다
- 심사·시연에서 언제든 열리는 **고정 주소**
- 10월 실회선 다지점 송출의 **송출 원점**

### ④ KOREN 실회선 — 10월 실측

지금 화면(`LiveConsole`, `NetworkPanel`)의 NIA POP 10개소 지연은 **서울 기준 거리 추정치**이고,
화면에 "실증 단계에서 KOREN 실회선으로 대체됩니다"라고 명시돼 있다.

> "메모리는 남고 연산이 부족한 자원이었습니다. 35GB 중 모델은 2.8M 파라미터라
> 한참 남습니다. 그래서 **모델을 키우는 대신 배치를 키워** 처리량을 올렸습니다.
> 메모리가 남는다고 모델을 키우면 이 슬라이스에서는 느려지기만 합니다.
> 그리고 GPU 할당량이 1개라, 인식 학습과 번역 학습을 **같은 슬라이스에서 동시에**
> 돌렸습니다. 병목이 서로 달라서(로더 vs 행렬곱) 가능했습니다."

### Q8. 자원을 효율적으로 썼다는 근거는?

- 플랫폼 **모니터링**으로 GPU 사용률 확인 → 낮으면 데이터로더 병목이라 `--workers` 조정
- 원본 **압축 해제 없이** 스트리밍 처리 → 수백 GB 디스크 절약
- 볼륨 운영 원칙: **홈은 pip 패키지 전용**(워크스페이스 삭제 시 함께 사라짐),
  코드·팩·체크포인트는 사용자 볼륨
- 장시간 학습은 셸이 아니라 **잡 스크립트**로 (`ml/jobs/train_*.sh`) → 세션이 끊겨도 안 죽음
- 두 모델 동시 학습으로 유휴 시간 제거

>
> 목표는 전 POP 종단 1초 이내로 잡고 있습니다. **다만 이건 목표치이지 실측치가
> 아닙니다** — 재고 나서 말씀드리겠습니다."

### Q10. HPC의 V100도 붙일 수 있는데 왜 안 썼나?

> "쓸 수 있고, 하이퍼파라미터 변형을 병렬로 돌리는 용도로 검토했습니다. GPU 할당량이
> 1개라는 제약을 우회하는 방법입니다. 다만 **V100은 Volta 세대라 bf16 연산이 없어서**
> `--amp fp16`으로 바꿔야 하고, 학습 스크립트가 fp16일 때만 GradScaler를 켜도록
> 이미 만들어 뒀습니다. 이번 기간에는 본 실험이 한 번에 수렴해서 병렬 탐색이
> 필요하지 않았습니다."

### Q11. KOREN이 아니어도 상용 클라우드로 할 수 있지 않나?

> "할 수는 있지만 두 가지가 다릅니다. 첫째, **비용**입니다. 133GB 수신과 60에폭 학습을
> 학부 팀이 상용 GPU로 감당하기 어렵습니다. 둘째, 이 과제의 서비스 형태는
> **전국 다지점 동시 송출**인데, 그걸 실회선에서 재 볼 수 있는 곳이 KOREN입니다.
> 상용 클라우드에서는 '지연이 이 정도일 것이다'까지밖에 못 씁니다."

### Q12. 전송량 2.4KB의 근거는?

> "프레임당 155개 실수값의 랜드마크 특징이고, 문장 단위로 묶었을 때의 크기입니다.
> 같은 내용을 수어 통역 **영상**으로 보내면 약 2,000배입니다. 다만 실회선에서 잰
> 값이 아니라 데이터 크기로 계산한 값이고, 10월에 실측으로 대체합니다."

### Q13. 저지연이 수어 통역에 왜 중요한가? 몇 ms가 필요한가?

솔직하게 — 우리가 재지 않은 것이다.

> "저희가 KOREN에서 얻는 이득은 지연보다 **동시성과 저대역**이 큽니다. 재난문자는
> 초 단위 서비스이지 밀리초 단위 서비스가 아닙니다. 대신 재난은 **전국에서 동시에**
> 일어나고, 통역사 배치로는 감당이 안 되는 지점이 정확히 거기입니다.
> 사람 수에 제약받지 않고 다지점으로 동시에 나가는 것 — 그게 저희가 망에서 필요한
> 것이고, 10월에 그 부분을 재려고 합니다."

### Q14. 학습을 KOREN에서 했다는 증거가 있나?

> "저장소에 운영 문서와 잡 스크립트가 있습니다. `ml/KOREN_SETUP.md`는 볼륨 구성부터
> MIG 특성, 실제로 밟은 함정까지 적혀 있고, `ml/KOREN_RESOURCES.md`는 자원 3종의
> 역할 분담입니다. 학습 로그와 각 판단의 근거는 `DECISIONS.md`에 시간순으로
> 남겼습니다 — **왜 붙였는지뿐 아니라 왜 안 붙였는지까지** 적혀 있습니다."

### Q15. 자원을 더 준다면 무엇을 하겠나?

> "세 가지가 바로 대기하고 있습니다.
> ① **GPU 슬라이스 추가** — 지금은 1개라 인식과 번역을 같은 슬라이스에서 나눠 돌렸습니다.
>   병렬 실험이 되면 연속 인식(CTC) 클래스 집합을 배포본 13,576종에 맞춰 재학습할 수
>   있습니다. 지금 그게 안 돼서 학습을 마친 모델을 못 붙이고 있습니다.
> ② **HPC VM 대수** — 수어영상 전량(sen 포함 약 300GB) 변환이면 4대로는 부족합니다.
> ③ **KOREN VM + 실회선** — 다지점 송출 실증."

이 답은 "자원이 왜 더 필요한가"를 **구체적인 막힘**으로 설명하기 때문에 강하다.
막연히 "더 주시면 더 잘하겠습니다"는 감점이다.

## 4. 절대 하면 안 되는 말

| 하면 안 되는 말 | 대신 |
|---|---|
| "HPC로 분산 처리했습니다" | "분산 구성을 마쳤고 8월 4주에 제출합니다" |
| "POP 지연 3ms를 측정했습니다" | "화면 수치는 시뮬레이션이고 10월에 실측합니다" |
| "KOREN VM에서 서비스 중입니다" | "9월부터 운영합니다. 현재는 정적 사이트로 배포돼 있습니다" |
| "실시간 저지연을 달성했습니다" | "단말 내부 번역은 문장당 144ms로 실측했고, 망 구간은 10월에 잽니다" |
| "자원이 부족했습니다" (변명조) | "메모리는 남고 연산이 부족한 자원이라, 거기에 맞춰 구조를 골랐습니다" |

## 7. 3단 폴백을 물으면 (07쪽 그림)

발표 자료에 그림으로만 있어서 "그게 뭐냐"가 나올 수 있다. **사전이 두 개**라는 점을
먼저 정리하지 않으면 설명이 엉킨다.

```
한국어 문장 ──[3단 폴백]──▶ 글로스 열 ──[동작 사전]──▶ 관절 좌표 ──▶ 아바타
              ↑ 여기가 3단                ↑ 폴백 아님. 항상 거친다
```

| 이름 | 파일 | 내용 |
|---|---|---|
| **번역 사전** (폴백 2단) | `align.json` · 23만 낱말 | 한국어 낱말 → **글로스 이름** (`한파`→`춥다1`) |
| **동작 사전** (폴백 밖) | `bank.json` · 12,833종 | 글로스 이름 → **관절 좌표** |

**① 학습 모델** `nnSignAgent.ts` · t2gs-v2 int8 30MB — 한국어 음절 → 글로스 seq2seq.
사전이 원리적으로 못 하는 것을 한다. 사람 번역가의 글로스에는 **한국어에 대응 낱말이
없는 것**이 섞이기 때문이다.

    원문   대설과 한파로 도로가 얼어 미끄러우니…
    사람   눈내리다 온도내려가다 춥다 [자연] 길 얼음 운전 [손 자동차] 미끄럽다 조심…

`자연`(원인 표지)·`손 자동차`(운전 분류사)는 짝이 되는 한국어 낱말이 없다.

**② 통계 사전** `dictSignAgent.ts` — AI Hub 16만 문장쌍에서 한국어 낱말과 글로스의
공기 빈도를 **Dice 계수**로 재어 만든 대응표. 어순은 못 배우지만 어휘 대응은
실데이터에서 나온 값이다.

**③ 규칙** `signAgent.ts` (40줄) — 조사·어미를 떼고 동의어를 정규화해 한국어 낱말을
그대로 글로스 이름으로 쓴다(`대피하세요`→`대피`). **사전 파일 자체를 못 읽었을 때만**
도는 안전망이라 정상 상태에서는 실질적으로 쓰이지 않는다.

**언제 아래로 떨어지나 — 조건이 코드에 박혀 있다**

| ①→② | 근거 |
|---|---|
| 도메인이 재난문자가 아니면 **애초에 모델을 안 쓴다** | 모델이 재난 말뭉치로만 배워 밖에서는 자신 있게 틀린다 (`화장실이 어디예요` → `꽃 꽃 지도 지시# 물…`) |
| 모델 30MB가 아직 안 받아졌을 때 | 첫 문장을 기다리게 하지 않는다. 사전으로 즉시 답하고 모델은 뒤에서 받는다 |
| 출력이 **무너졌을 때** (`degenerate()`) | `<unk>` 포함 · 같은 낱말 3연속 · 한 낱말이 전체의 절반 초과 |
| ②→③ | `align.json`을 못 읽었을 때뿐 |

세 번째가 핵심이다. 분포 밖 문장에서 모델은 `꽃 꽃 꽃 …(47개)` 같은 반복 붕괴에 빠지는데,
그게 아바타로 나가면 **뜻 없는 동작을 47번 반복**한다. 모양으로 알아채고 사전으로 되돌린다.

**순위 근거**: 사전 대비 모델 글로스 F1 **18.7 → 55.8**(실측).

**따라오는 질문 — "모델이 조용히 빠져도 화면은 똑같지 않나?"**

> "맞습니다. 그래서 **어느 단계가 답했는지를 화면 속성으로 남깁니다**(`lastBackend`).
> 자동 검사가 그 값을 읽어 확인합니다. 행동요령이 모델로 새는지 보는 검사
> (`check_guide_domain.mjs`)가 따로 있는 이유도 같습니다 — 한동안 행동요령이
> 모델로 가서 '엘리베이터를 타지 말고 계단으로 대피하세요'가 엉뚱한 글로스로
> 나갔습니다. 목숨이 걸린 안내라 도메인으로 분기했습니다."
